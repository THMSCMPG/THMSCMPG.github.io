Why Layer 3, not Layer 4?

Rust is the user-facing shell but it depends on the C ABI (Layer 4) to safely perform OS-level process management. Layer 4 provides the stable interface; Layer 3 consumes it.

Why Does Layer 4 Have the Highest Number?

In the handbook's architecture table, Layer 4 is listed first — at the top — because it is the outermost, user-visible ABI surface. Its number reflects architectural position in the abstraction stack, not call order.

The C layer is called by Rust (Layer 3) at runtime, but it is numbered 4 because it is the stable public contract: "The stable ABI that insulates Rust from OS details." Any future GUI technology (Layer 3 replacement) would still use this same C header without changes.

Think of it like POSIX system calls — they are a lower-level primitive but form the outermost stable interface in the OS abstraction model.

Simulation Modes

SimV0: Baseline Single-Diode
Single-diode equivalent-circuit model — fastest path for clear-sky, low-accuracy estimates
Status: Complete
Runtime: < 1 ms per timestep
Use case: Clear-sky, low-accuracy path; PINN routing baseline
Implemented:
  • Single-diode model: I = I_ph − I_0(e^((V+I·Rs)/n·Vt)−1) − (V+I·Rs)/Rsh
  • STC-calibrated parameters for standard silicon cells
  • No BTE, no thermal solver — algebraic only
SimV1: Full High-Fidelity
3D BTE Monte Carlo + Crank-Nicolson heat + Navier-Stokes + adjoint sensitivity
Status: 90% Complete
Runtime: 15–45 minutes (grid-dependent)
Use case: Highest accuracy; adjoint-guided parameter studies
Implemented:
  • BTE MC (AM1.5G CDF sampling, Beer-Lambert α=1e5 m⁻¹, Fresnel at all interfaces)
  • Crank-Nicolson θ=0.5 3D heat (ADI splitting, unconditionally stable)
  • Navier-Stokes with Boussinesq buoyancy, CFL sub-stepping
  • Lagrange multiplier adjoint: dJ/d[k_thermal, alpha, h_conv]
  • Perez POA + Fresnel IAM + Faiman thermal (Python Stage 1)
Open: Gap 3 — M_spectral hardcoded 1.0 (~5% photon energy error); Gap 4 — adjoint gradient check bypassed at call site
SimV1b: SimV1 + Spectral Inversion
SimV1 high-fidelity pipeline augmented with spectral inversion layer for mismatch correction
Status: In Progress
Runtime: ~20–50 minutes (adds spectral inversion post-pass)
Use case: Spectral mismatch correction under non-STC atmosphere (resolves Gap 3 pathway)
Implemented:
  • Full SimV1 BTE MC + CN heat + NS physics
  • Spectral inversion pass: M_spectral correction applied to absorbed photon flux
  • Reads M_spectral from fortran_bc.csv col 3 (Gap 3 resolution path)
SimV2: Multi-Fidelity + PSO
Alternates LF Beer-Lambert and HiFi BTE MC; Particle Swarm Optimization with CP-ALS surrogate
Status: 95% Complete
Runtime: ~5–10× faster than SimV1 for equivalent design search
Use case: Panel design optimisation; parameter screening
Implemented:
  • Clerc constriction PSO (w=0.729, c1=c2=1.49445, theoretically stable)
  • LF/MF/HF alternating fidelity with T_corrected blending
  • CP-ALS tensor surrogate for fitness landscape approximation
  • PSO fitness: J = w_T·RMSE + w_cost·t_cpu + w_unif·uniformity
  • Latin Hypercube Sampling for initial Python-side sampling
SimV2b: Sandia + IIR Filter
Sandia empirical PV model augmented with an IIR low-pass filter for noisy or rapidly changing inputs
Status: In Progress
Runtime: ~5–10× faster than SimV1; filter adds < 1% overhead
Use case: Noisy/rapidly-changing environmental input; sensor fusion path
Implemented:
  • Sandia Array Performance Model (SAPM) empirical core
  • Infinite Impulse Response (IIR) low-pass filter on irradiance and temperature inputs
  • Filter coefficients tunable via run_config.json
SimV3: Bayesian Optimisation
Kennedy-O'Hagan co-Kriging GP surrogate + EI/UCB/PI/PIAF acquisition; --fidelity override resolved
Status: 90% Complete
Runtime: Optimal accuracy/cost; GP_MAX_TRAIN capped at 200 points
Use case: Global optimum search with uncertainty quantification
Implemented:
  • Kennedy-O'Hagan co-Kriging: f_HF(x) = ρ·f_LF(x) + δ(x), Cholesky solve
  • Acquisition: EI (Mockus 1974), UCB (κ=2), PI, PIAF (penalises T_cell > 85°C)
  • MCMC (Adaptive M-H): R-hat + ESS diagnostics, posterior UQ
  • --fidelity 0/1/2 CLI flag (Gap 2 resolved)
  • Writes simv3_gp_diagnostics.csv and simv3_summary.csv
SimV3b: Sandia + Fuentes Thermal Correction
SimV3 Bayesian Optimisation with Fuentes thermal mass correction for full thermal inertia modelling
Status: In Progress
Runtime: GP_MAX_TRAIN capped at 200 points; Fuentes adds minimal overhead
Use case: Full thermal mass correction; high-accuracy thermal tracking
Implemented:
  • Kennedy-O’Hagan co-Kriging GP surrogate (same as SimV3)
  • Fuentes (2003) thermal model: accounts for thermal mass, wind, mounting configuration
  • T_cell corrected for thermal lag vs. steady-state SAPM estimate
SimV4: Fortran + PINN Weights Router
DualHead PINN predicts T_panel and emits an 8-way routing probability vector across all tiers
Status: 80% Complete
Inference time: < 5 ms (weights embedded at compile time)
Use case: Maximum fidelity, PINN-guided tier selection
Implemented:
  • DualHead PINN: predicts T_panel; outputs 8-way routing probability vector — one logit per tier: simv0, simv1, simv1b, simv2, simv2b, simv3, simv3b, simv4 (routing to simv4 means "run maximum-fidelity PINN pass")
  • PINN weights embedded at compile time via pinn_weights_module.f90
  • Inference < 5 ms — suitable for closed-loop edge deployment
  • Routing selects the most appropriate fidelity tier per inference step
  • Decision tree fallback policy (sigma_frac/R2/n_HF heuristics) retained as safety net
